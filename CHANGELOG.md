## [2026-10-16]

### Feature
- Served the home page, `/about` and `/seminars` as static assets instead of rendering them in the Worker. On the Workers Free plan every Worker call spends one of 100,000 requests a day, while static asset requests are free and unlimited, so these three pages no longer use that budget however many people visit. They are prerendered from a snapshot of the public seminar list: `scripts/export-public-content.mjs` reads it from D1 into `src/generated/public-seminars.json` (gitignored) before `npm run build`, `dev` and `start`. The source is chosen by environment: production D1 when `CLOUDFLARE_API_TOKEN` is set, else the local D1 when `.wrangler/state` exists, else an empty snapshot (PR builds), and `TCN_CONTENT_SOURCE=remote|local|empty` overrides it. The `Build` step of `deploy-workers.yml` sets `TCN_REQUIRE_CONTENT=1`, which allows only production D1 and fails the build when it cannot be read, so an empty list or local test data cannot be published. The script runs the same SQL as the Worker (`src/lib/db/post-sql.ts`) and shares `src/lib/public-content/core.ts`, which Node runs directly, so that file may only use type imports. Upcoming, today and held are computed from the date the snapshot records, not the build clock. `/seminars/<date>`, `/media/*` and the APIs stay server-rendered on purpose: `npm run verify:admin` pins "publish shows at once, delete is a 404 at once", and the per-view photo revalidation chosen on 2026-07-27 is kept. The cost is that a changed title, summary, address or date reaches the three static pages after up to about 15 minutes. Checked: 423 tests pass above the coverage thresholds, `astro check` reports 0 errors, the production build, and on a local `wrangler dev` build `verify` (9 routes at 3 widths and 8 redirect and 404 contracts), `verify:founding-media`, `a11y`, `verify:seminar-carousel` and `verify:admin`; adding a seminar to the local D1 made the freshness check report stale, a rebuild fixed it, and the live fingerprint computed in the Worker equalled the one the Node script baked. Not checked: the new workflow on GitHub Actions, a production deploy (the build now reads production D1 with the deploy token), and `/api/content-fingerprint` on production. (Branch: `perf/static-public-pages`) - Implemented by Claude
- Added the `refresh-static-content.yml` workflow, which keeps those static pages current. Every 10 minutes it compares `/api/content-fingerprint` (a hash of the live seminar list plus the Seoul date, computed from D1) with `/content-fingerprint.json` (the same hash baked into the deployed build) and dispatches `deploy-workers.yml` when they differ, so adding, editing or deleting a seminar, or the date rolling over, redeploys within about 15 minutes. It needs no Cloudflare secret (`contents: read` and `actions: write` only). It skips while a deploy is queued or running, does not dispatch again within 15 minutes of a dispatch that left the pages stale, and fails without deploying when either fingerprint cannot be read, so an outage is not mistaken for a change. It polls the `workers.dev` address the deploy smoke test uses, so the two must move together when `workers.dev` is turned off; GitHub also pauses scheduled workflows after 60 days without repository activity. (Branch: `perf/static-public-pages`) - Implemented by Claude

## [2026-10-15]

### Feature
- Added a baseline set of security headers to every response. Before this, only the Q&A routes carried any (`nosniff`, `Referrer-Policy`, and a CSP limited to `frame-ancestors`, `base-uri` and `object-src`); every other page and API response had none. The shared set lives in `src/lib/security-headers.ts`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, a `Permissions-Policy` that turns camera, microphone, geolocation, payment and usb off, `Strict-Transport-Security: max-age=31536000` (no `includeSubDomains` or `preload`, which are not commitments to make blindly), and the enforced CSP above. Responses the Worker renders get it from `src/middleware.ts`, including the canonical redirect and responses with immutable headers, and the response is mutated in place so cookies Astro attached to it survive. Prerendered pages are served by Workers Static Assets and never reach the middleware, so `public/_headers` carries the same set under `/*`; a test fails if the two drift apart. A header a route already set wins over the baseline, and the Q&A block in the middleware is reduced to `Cache-Control: no-store`. The full CSP (`'self'` plus the Turnstile origin) ships as `Content-Security-Policy-Report-Only` first. It still allows `'unsafe-inline'` because the Astro islands, the theme bootstrap and the Q&A form script are inline, so it cannot be enforced until those are hashed (Astro's `security.csp` is the likely route; it emits a `<meta>` tag, which cannot carry `frame-ancestors` or Report-Only). Checked on a local `wrangler dev` build: headers on static, SSR, asset, redirect and 404 responses, and zero Report-Only violations on the public pages, the Q&A form (the Turnstile widget loads) and the admin login in light and dark, with a deliberate external image and script as a control that the probe does see violations. Not checked: production responses, signed-in admin screens (the Tiptap editor and media upload) and seminar posts with user content. Violations are only visible in the browser console because there is no report endpoint. (Branch: `chore/update-deps`) - Implemented by Claude
