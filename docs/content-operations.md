# 콘텐츠 운영 가이드

콘텐츠를 누가 어떻게 바꾸는지, 작성자가 글을 올리면 무엇이 바뀌는지, 계정을 어떻게 발급하는지 정리합니다. 콘텐츠 종류별 저장 위치(D1 테이블·정적 데이터·카피 파일)는 [`CONTENT_ARCHITECTURE.md` §3](../CONTENT_ARCHITECTURE.md#3-데이터)가 단일 원천이라 여기서 되풀이하지 않습니다.

## 누가 무엇을 바꾸나

- 세미나·활동 글: 개발자 관여 없이 **작성자가 `/admin`에서 직접 등록** → 목록·홈·연혁·상세에 즉시 반영.
- 공개 Q&A: 방문자가 `/questions/new`에서 제출(Turnstile·레이트리밋 통과 시) → 운영자가 `/admin/questions`에서 답변·숨김 처리. 새 질문은 알림이 가지 않고 어드민 내비의 대기 건수 배지로만 드러납니다.
- 소개 페이지 카피·임원·연혁·초청장: 코드 저장소 파일 수정(§3의 파일 목록 참고) 후 배포.

## 관리자 세미나 글 등록 시 영향 범위

`/admin`에서 세미나를 저장하면 별도 배포 없이 즉시 공개됩니다.

- 개최일은 실제 존재하는 날짜여야 하며(예: `2026-11-31` 불가), 기존 마지막 세미나보다 뒤여야 합니다.
- 회차와 공개 URL(`/seminars/YYYY-MM-DD`)은 개최일순으로 자동 생성됩니다.
- 홈은 미래 세미나 중 개최일이 가장 가까운 한 건을 차기 세미나로 표시합니다. 예: 제2차 `2026-10-30`, 제3차 `2026-11-30`이면 `2026-10-30`까지 제2차가 표시되고 `2026-10-31`부터 제3차로 넘어갑니다.

| 대상                  | 반영 내용                                    |
| --------------------- | -------------------------------------------- |
| 홈 `/`                | 가장 가까운 차기 세미나와 최근 세미나 표시   |
| 세미나 `/seminars`    | 예정·지난 세미나 목록에 자동 분류            |
| 연혁 `/about#history` | 기관 연혁에 세미나 항목 추가                 |
| 상세 페이지           | 날짜 기반 공개 URL과 본문·미디어 페이지 생성 |

또한 sitemap과 관리자 글 목록이 갱신되며, 설정된 경우 Discord·Telegram 알림이 발송됩니다.

## 작성자 계정·시드

회원가입 UI가 없습니다. 최고관리자가 계정을 수동 발급합니다.

```bash
# 작성자 계정 발급 (--remote 없으면 로컬 D1)
# 비밀번호는 인자로 받지 않는다 — 터미널에서 실행하면 숨김 입력으로 두 번 묻는다.
node scripts/create-user.mjs <아이디> --remote --display "이름"

# 세미나 글 시드 (멱등)
node scripts/seed-seminar-posts.mjs --remote
```

비밀번호 정책(`src/lib/auth/password-policy.ts`): 12자 이상, 아이디 미포함, 흔한 비밀번호(`password1234` 등)·단순 반복·순서 거부. 자동화에서는 `TCN_USER_PASSWORD` 환경변수로 넘깁니다(`read -rs TCN_USER_PASSWORD; export TCN_USER_PASSWORD`처럼 넣으면 셸 히스토리에도 남지 않습니다). 로그인 방어(챌린지·잠금·신뢰 기기)는 [`operations-runbook.md`](./operations-runbook.md#administrator-sign-in)를 보세요.

작성자는 `/admin`에서 로그인 → 글 작성(제목·개최일·주소·본문) → 사진·영상·문서 드래그앤드롭 업로드(이미지는 WebP 자동 변환) → 저장 시 즉시 공개됩니다. 권한은 flat(인증된 회원 누구나 등록·수정), 삭제는 soft delete입니다.
